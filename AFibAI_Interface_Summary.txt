AFibAI SYSTEM INTERFACE — DETAILED SUMMARY

Overall System

The project should have three interfaces serving three different purposes:

Wio = immediate monitoring
Patient phone = simple understanding + history
Doctor computer = detailed clinical/research analysis

System flow:

Patient
  ↓
ECG electrodes
  ↓
AD8232 ECG sensor
  ↓
Wio hardware
  ↓
ECG data / features
  ↓
Server
  ├── XGBoost
  ├── CatBoost
  └── SHAP
  ↓
Patient Phone + Doctor Computer
  ↓
Turso database

Render hosts the web application.


==================================================
1. WIO INTERFACE — THE DEVICE
==================================================

Purpose:

The Wio should answer:

"What is happening right now?"

It is the immediate monitoring interface, not the place for detailed analysis.

Wio Main Screen:

- AFibAI
- ECG Monitoring
- Heart Rate
- R-R Interval
- Signal Quality
- AFib Status
- Recording button

Recommended information:

1. Heart Rate
   Example: HR 78 BPM

2. R-R Interval
   Example: R-R 820 ms

3. Signal Quality
   - GOOD
   - WEAK
   - POOR

4. AFib Result
   - NOT DETECTED
   - POSSIBLE AFib

5. Recording Status
   - READY
   - RECORDING
   - Recording time

During Recording:

- Recording timer
- Heart rate
- Signal quality
- Small real-time ECG preview
- Stop recording button

After Recording:

- AFib result
- AFib probability
- Heart rate
- Signal quality
- View details
- New recording

If SHAP is shown on Wio, keep it very simple.

Example:
"Why flagged?"
"R-R irregularity ↑"

Do NOT put these on the Wio:

- Poincare plot
- Full SHAP graph
- RMSSD
- SDNN
- Model selection
- XGBoost/CatBoost buttons
- Dataset information
- Sampling rate settings
- CSV controls
- NPY upload
- Technical debugging information

6. THE THREE INTERFACES IN ONE SENTENCE
==================================================

Wio:

"Measure me and tell me what is happening right now."

Patient phone:

"Tell me what my result means and show me my history."

Doctor computer:

"Give me the detailed evidence behind the result and the patient's history."


==================================================
7. RECOMMENDED SYSTEM CONCEPT
==================================================

The system separates information according to the user's needs.

The Wio provides immediate physiological feedback during ECG acquisition.

The patient-facing mobile interface provides simple and understandable results and recording history.

The clinician-facing dashboard provides detailed ECG, HRV, machine-learning and explainability analysis for further review.


==================================================
8. IMPORTANT AI TERMINOLOGY
==================================================

If your XGBoost/CatBoost models classify the CURRENT ECG recording as AFib vs non-AFib, the interface should say:

- Possible AFib
- AFib detected by the model
- AFib probability
- Recording flagged for review

Do not describe the output as predicting future AFib onset unless the model was specifically trained and validated for future-onset prediction.

Also, the system should be presented as a research/screening prototype rather than a medical diagnosis tool.
